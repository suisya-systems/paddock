# Why org-clone is built this way

- **A separate script, `org-delegate` unchanged.** `org-delegate` exits 2 before it creates anything when `--project` names nothing known, and its exit codes are the secretary's contract. A clone is a network step with its own failures, so it runs first, on its own, and delegation starts only when it printed a name.
- **GitHub only, `OWNER/NAME` or a URL, bare names asked back.** A bare name matched against a search would guess which of several repositories is meant and then run code from it. Another host needs its own credentials and name rules; add it when a request names one.
- **`<projects dir>/<owner>/<name>`, outside the workers folder.** The workers folder holds throwaway worktrees and its trust is not what lets a worker start; a permanent clone does not belong in it. `<owner>/<name>` keeps two repositories with the same name apart; the registry name is `NAME`, and a second `NAME` stops at exit 7 instead of overwriting.
- **The secretary's own login clones; a worker holds nothing.** The clone runs in the shell where `gh` and `git` already work. A repository that login cannot read fails at the clone; there is no second credential and no retry.
- **`.partial`, then rename.** A failed or killed clone never looks like a finished one: the target path appears only after the git check passed, and the row is written after that. A leftover `.partial` is the script's own and is removed on the next run.
- **The trust marker, and no automatic yes.** The existing prompt path presses "Yes, I trust this folder" by itself for a clone a person made. For a clone made because a request named a repository, that would trust code nobody looked at, so the dialog is held for an approval card. The marker lives in the clone's git folder because every worktree of the clone shares it (`git rev-parse --git-common-dir`); deleting it after the first yes means later workers are not asked again, and a no leaves it. The `answer` of a folder-trust prompt moves the cursor with `down` and re-reads before `enter`, as the policy does, because the dialog's default is "No, exit".
- **Clone what is named.** A fork is not looked for. If the login cannot push to the named repository, that shows at the pull-request step, after the work; the secretary reports it and stops.
