# Why org-update-branch is built this way

- **A merge, not a rebase.** Once a branch is pushed and main has moved, the secretary cannot force-push a rebase, so main is merged in and the next push is a fast-forward.
- **The protected-path preflight.** In a worker, the sandbox protects `.claude/skills/**`, `.claude/hooks/**`, `.claude/settings.json` and `.claude/settings.local.json`; an incoming range that touches one stops a rebase (and a merge writes them the same way). The script names them and refuses, leaving the branch unchanged, instead of failing halfway. The secretary runs the same command outside the sandbox, where the check is off. The list is fixed in the script, not read from what the sandbox places (which would be better): add a path to the script's `grep` when a new one is measured. A worker is told apart by `PADDOCK_ORG`; a secretary shell with that variable set would be checked like a worker (harmless: it only refuses).
- **The acceptance gate and a merge.** The predecessor's gate (`acceptance_gate.py`, `check_first`) required the test commit's parent to equal the merge-base, and a merge moves the merge-base to main's tip, so a merge made here does not ride the automatic merge in `acceptance` mode; a person decides that PR. While nothing is pushed, the worker rebases (no force needed, test commit stays first); once pushed, run this tool only when a person will decide the merge. A gate that served this tool would need to accept a test-commit parent that is an ancestor of base (not equal to the merge-base), ignore join commits before the test commit on the first-parent line, and check declared and protected paths against the branch's own commits only, not at changes that came in from base.
- **Every exit says what to do next.** One `next:` line on every exit (decision 0014), so the secretary reads one line instead of a table; the table of exit codes is in `--help`.
- **Measured.** On a host 2026-11-14 (`docs/design/acceptance-mode-probe.md`): a real push after the merge, and `PADDOCK_ORG` in a real worker session (the protected-path stop, and the merge that goes on without a fetch). Also tested against a local bare repository (`tests/org-update-branch.test.sh`, `tests/org-update-branch-worker-fetch.test.sh`, `tests/org-update-branch-next.test.sh`). Not measured: how the gate treats files that arrive through the merge (they are main's, not the branch's).
