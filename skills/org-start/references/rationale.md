# Why org-start is built this way

- **Refuse inside an agent.** The first `hc` command starts a core if none runs, and that core inherits the shell's environment. A core started from an agent would carry the agent's session variables into every terminal, so the script refuses when they are set. It cannot yet tell whether a running core was started that way; the template's `env -u ...` prefix is the second line of defence.
- **Notes off.** The core's notes feature must be off in its own config. org-start checks and says what to add but never writes the core's config, which is the person's.
- **Role files live in the bin folder, not beside the templates.** The worker settings deny reading the core's folder, so a worker could not run the org script there; and the core lists every `*.md` in its templates folder as a template, so a rules file there showed up as a broken one. The bin folder is denied for writing, so a worker cannot rewrite its own rules or settings.
- **Absolute paths of `claude` and `codex` are recorded.** Templates and the review gate run in shells whose `PATH` may lack them; recording the path at start removes that dependence and gives a clear error when `claude` is missing.
- **Folder trust for the secretary only.** A new terminal in an untrusted folder stops at Claude Code's trust dialog and the first message never arrives. org-start answers it once, for the secretary's own root, with a screen read, a cursor check and no blind Enter. Worker worktrees get no keys from org-delegate: trust there follows the project, and the secretary's prompt skill handles a dialog that does appear.
- **The secretary's `--cwd` is the paddock folder,** so it finds the org script and the skill scripts whatever folder org-start ran from. A finished secretary terminal is removed before a new one starts.
- **The mod is placed, not opened.** Opening the dialog is a separate herdr-app step that can toggle; it is not scripted until an idempotent form is measured.
- **A worker holds no GitHub credential.** It reads its base from the project clone's `origin/*`, which the secretary fetches, so org-start asks the person for no token.
- **A worker writes only its own files in the state folder,** named in its own settings file, so the shared settings never grant the state folder to the sandbox.
- **Layout and secretary prop.** An installed layout's `"secretary"` prop is kept on reinstall; when the app sees the core as another machine, the prop is written `<machine>/<secretary name>`; on WSL the Windows app is used when only its socket exists.
